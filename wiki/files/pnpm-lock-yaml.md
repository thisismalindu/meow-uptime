# `pnpm-lock.yaml` — pnpm dependency snapshot

This 499-line YAML file is generated by **pnpm**, a package manager alternative to npm. The application, Dockerfile, and CI currently use npm, so `package-lock.json` is the lockfile those paths consume.

## Representative source from the top

```yaml
lockfileVersion: '9.0'

settings:
  autoInstallPeers: true
  excludeLinksFromLockfile: false

importers:

  .:
    dependencies:
      '@supabase/supabase-js':
        specifier: ^2.112.3
        version: 2.112.3
      express:
        specifier: ^4.21.2
        version: 4.22.2

packages:

  '@supabase/auth-js@2.112.3':
    resolution: {integrity: sha512-...}
    engines: {node: '>=22.0.0'}
```

The integrity value is abbreviated only in this educational excerpt.

## Line and section walkthrough

- `lockfileVersion` identifies pnpm's generated schema.
- `settings` records resolution behavior so another pnpm install behaves consistently.
- `autoInstallPeers` controls automatic installation of peer dependencies.
- `excludeLinksFromLockfile` controls whether linked package information is recorded.
- `importers` lists workspace projects; `.` means this repository root.
- Under an importer's `dependencies`, `specifier` preserves the range requested in `package.json` and `version` records the exact selection.
- `packages` describes every resolved package release.
- `resolution.integrity` verifies downloaded content.
- `engines` records runtime requirements.
- Later `snapshots` entries describe the concrete dependency graph: which exact packages depend on which other exact packages.

Indentation creates YAML nesting. Repeated dependency entries and hashes use those same meanings throughout the remaining generated lines.

## Why having two lockfiles matters

pnpm resolved Express 4.22.2 here, while npm's lock records 4.21.2. Two developers using different managers can therefore run slightly different dependency trees. The current operational path says npm: `npm start`, `npm ci` in Docker, and `npm ci` in GitHub Actions. A cleanup should deliberately choose one manager, regenerate its lock, verify tests, and remove the unused lock rather than casually deleting files.
