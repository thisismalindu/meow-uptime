# `supabase-setup.sql` — database schema

SQL is the language used to define and query relational databases. Run this file in the Supabase SQL Editor once to create the table expected by the JavaScript code.

## Complete source

```sql
create table sites (
  id bigint generated by default as identity primary key,
  url text not null,
  status text not null default 'UNKNOWN',
  status_code integer,
  latency_ms integer,
  last_checked timestamptz,
  failure_count integer not null default 0,
  incident boolean not null default false,
  created_at timestamptz not null default now()
);
```

## Line-by-line walkthrough

- **Line 1:** Create a table named `sites`; the opening parenthesis begins its column list.
- **Line 2:** Create a large integer ID. `identity` lets PostgreSQL generate successive values, and `primary key` makes each row uniquely addressable and indexed. “By default” still allows an explicit ID when needed.
- **Line 3:** Store the URL as arbitrary-length text and forbid null/missing values.
- **Line 4:** Store a required status string and use `UNKNOWN` when an insert omits it.
- **Line 5:** Store the latest whole-number HTTP status code. With no `not null`, network failures may store null.
- **Line 6:** Store the latest whole-number duration in milliseconds, also nullable.
- **Line 7:** Store when checking was attempted. `timestamptz` represents an absolute moment and converts for session timezone display.
- **Line 8:** Store a required consecutive-failure count, initially zero.
- **Line 9:** Store a required true/false incident flag, initially false.
- **Line 10:** Store insertion time and let the database clock fill it automatically with `now()`.
- **Line 11:** Close the column list and end the SQL statement with a semicolon.

## Why defaults are useful

The POST route only inserts `{ url }`. Database defaults make every other required value valid even if another client inserts a row. The database is the final guardian of its invariants.

This schema does not add history, uniqueness, URL format constraints, indexes beyond the primary key, Row Level Security policies, or an automatic update timestamp. Those are conscious limitations to address before production use.
